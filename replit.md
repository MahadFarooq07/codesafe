# CodeSafe

A Chrome extension that reads one-time verification codes from the user's Gmail and shows them in an Apple-style pill above code inputs on any site for one-click autofill, plus a one-page landing site that hosts the download and the privacy policy.

## Run & Operate

- Landing page: workflow `artifacts/codetap-web: web` (`pnpm --filter @workspace/codetap-web run dev`), served at `/`
- Extension build: `pnpm --filter @workspace/codesafe-extension run zip` — builds `extension/dist` and writes `artifacts/codetap-web/public/codesafe-extension.zip` (what the "Add to Chrome" button downloads). Re-run after any extension change.
- Extension tests: `pnpm --filter @workspace/codesafe-extension run test` (extractor cases)
- `pnpm run typecheck` — full typecheck (note: the root filter covers `artifacts/**`; run `pnpm --filter @workspace/codesafe-extension run typecheck` for the extension)
- Explainer film: workflow `artifacts/codetap-video: web` at `/codetap-video/`. The exported MP4 lives in `artifacts/codetap-web/public/codesafe-film.mp4` (embedded on the landing page) and `docs/codesafe-film.mp4` + `docs/codesafe-demo.gif` (README). Re-export by recording the preview with Chromium (CDP screencast) + ffmpeg after film changes.
- `artifacts/api-server` exists from the template but is unused by this product (no backend by design).

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Landing page: React 19 + Vite 7 + Tailwind v4, wouter routing, no web fonts (system stack)
- Extension: Manifest V3, plain TypeScript bundled with esbuild (background = ESM service worker; content/popup/offscreen = IIFE). No runtime deps.

## Where things live

- `extension/` — the Chrome extension (`manifest.json`, `src/background` auth/gmail/extract/orchestration, `src/content` detector/fill/pill, `src/popup`, `public/` static popup + icons, `test/otp.html` manual test page, `README.md` setup guide)
- `extension/src/shared/tokens.ts` — design tokens shared by the popup CSS (substituted at build) and the pill's shadow root
- `artifacts/codetap-web/src/pages/home.tsx`, `privacy.tsx`, `components/site/*` — landing page
- `artifacts/codetap-web/public/codesafe-extension.zip` — generated by the extension build; don't hand-edit
- `.local/conversation-workspace/files/codesafe/` — original build plan and technical guides (Next.js guide is reference only; the site was built with the project's Vite stack)

## Architecture decisions

- No backend anywhere: the extension calls `gmail.googleapis.com` directly; the site is static.
- Privacy-minimal by design: `gmail.readonly` only; query `newer_than:10m` + code keywords, max 5 messages, snippet/metadata first and full body for the 2 newest only; searches run only on OTP-field focus, popup open, or shortcut; code kept in `chrome.storage.session` with a 5-minute alarm wipe; sender stored as domain only.
- Pill is rendered in a closed shadow DOM so pages can't restyle it or read the code.
- Autofill uses the native value setter + input/change events so React/Vue controlled inputs accept it; split 6-box inputs are detected via `maxlength=1` groups.
- esbuild instead of a Vite CRX plugin: MV3 content scripts can't be ES modules, and a plain multi-entry build is predictable.

## Product

- Pill design copies iOS's QuickType code suggestion: a two-line chip, "From Gmail" over the code, nothing else (dots while searching). The user asked for less text; keep it this minimal in the extension and on the site (shared site component `components/site/pill.tsx`).
- Landing page `/`: hero with looping code-built demo of the pill filling a 6-box field, "You already know how this works" section (iPhone keyboard suggestion next to Chrome pill), problem/how-it-works/keyboard/privacy/FAQ sections, "Add to Chrome" downloads the zip (no Web Store listing yet). `/privacy` policy page with Google Limited Use statement.
- Extension popup: signed-out → Continue with Google; idle/searching/none/found/error states; Copy code; toggles for "Show on code fields" and "Copy automatically"; Sign out. Shortcut ⌘⇧V / Ctrl+Shift+V pastes the latest code.

## User preferences

- Premium Apple-style white design everywhere (site and extension UI). Tokens: bg #FBFDFF/#FFF, text #1B1C1D, secondary #6E6E73, hairline rgba(0,0,0,.08), accent #0A84FF, success #34C759, radii 12/16/999, ease cubic-bezier(.2,.8,.2,1), system fonts. No emojis in UI.
- The extension should only surface the code from email and paste it — nothing more. Keep it non-invasive.
- "CodeSafe" is a working name; the user may rename.

## Gotchas

- Sign-in won't work until the user sets `oauth2.client_id` in `extension/manifest.json` (Google Cloud "Chrome Extension" OAuth client) and pins a manifest `key` for a stable extension ID — see `extension/README.md`.
- `gmail.readonly` is a Google restricted scope: public Web Store release needs OAuth verification + CASA; personal use works via test users with the "unverified app" interstitial.
- GitHub link in the site footer/nav is `#` until a repo exists.
